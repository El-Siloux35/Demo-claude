SplitText · type

Trois façons de découper la même phrase.

SplitText remplace le texte par des éléments imbriqués : une boîte par ligne, par mot ou par caractère, selon ce qu'on lui demande. Ce sont ces boîtes qu'on anime ensuite. Affichez-les pour voir ce que le plugin fabrique réellement.

Le découpage

Une phrase se découpe en lignes, en mots, puis en caractères.


        
Un découpage en caractères produit aussi les mots, car les caractères doivent bien être regroupés quelque part. Demander "chars" seul suffit donc rarement : c'est "chars,words" qu'on écrit en pratique.

      

    

  


  
  

    

      
SplitText · mask

      
Le masque change tout, et ne coûte qu'un mot.

      
Sans masque, un mot qui monte vient de nulle part : on le voit traverser l'espace au-dessus de sa ligne. Avec mask, SplitText enveloppe chaque unité dans une boîte qui coupe ce qui dépasse, et le texte semble surgir de derrière un bord net. Les deux cartes jouent la même animation.

    


    

      

        
Sans masque

        
Le texte arrive de nulle part.

        
type: "lines"

        
Les lignes montent depuis l'extérieur du cadre. Rien ne les arrête : on voit le mouvement d'approche.

      

      

        
Avec masque

        
Le texte surgit de derrière un bord.

        
type: "lines", mask: "lines"

        
Chaque ligne est enveloppée dans une boîte qui coupe le débordement. Le mouvement d'approche est caché, et la révélation est franche.

      

    


    

      

        

          
        

      

    

  


  
  

    

      
SplitText · stagger & propIndex

      
L'ordre d'entrée raconte quelque chose.

      
Une fois le texte découpé, ce n'est plus SplitText qui travaille mais le décalage de GSAP. Le même fondu change complètement de sens selon l'ordre dans lequel les caractères arrivent.

    


    

      

        
Ordre du décalage

        
Chaque ordre a son intention.

        

          
          
          
          
        

        

        
« Du début » se lit comme une frappe au clavier, « du centre » comme une ouverture, « au hasard » comme une matérialisation. Même durée, même fondu : seul l'ordre diffère.

      


      

        

          
propIndex · animer en CSS seul

          
        

        
Sans une ligne de JavaScript d'animation.

        
propIndex: true   → chaque caractère reçoit --char: 1, 2, 3…

.split-char {
  animation: rise .5s backwards;
  animation-delay: calc(var(--char) * 28ms);
}

        
Avec propIndex, SplitText écrit l'index de chaque unité dans une variable CSS. Le décalage se calcule alors en CSS, et l'animation tient sans GSAP — utile quand elle doit démarrer avant que le JavaScript ne soit prêt.

      

    

  


  
  

    

      
SplitText · autoSplit, onSplit, aria, ignore, revert

      
Ce qui fait qu'un texte découpé survit à la vraie vie.

      
Découper du texte le fige : les lignes ont été calculées pour une largeur donnée et une police donnée. Redimensionnez la fenêtre, ou laissez une police web finir de charger, et le découpage ne correspond plus à rien. C'est le problème que ces options résolvent.

    


    

      

        

          
autoSplit + onSplit · redimensionnez la fenêtre

          
        

        
Redimensionnez cette fenêtre : les lignes sont recalculées pour la nouvelle largeur, et l'animation se rejoue sur le nouveau découpage. Sans autoSplit, les lignes resteraient coupées comme au premier rendu, et le masque trancherait au mauvais endroit.

        
SplitText.create("#t-auto", {
  type: "lines", mask: "lines",
  autoSplit: true,
  onSplit(self) {
    // l'animation renvoyée est rejouée et nettoyée
    // automatiquement à chaque redécoupage
    return gsap.from(self.lines, { yPercent: 100, stagger: .1 });
  }
});

        
Renvoyer l'animation depuis onSplit plutôt que la lancer à côté, c'est ce qui permet à SplitText de la tuer proprement avant de redécouper. Sans cela, chaque redimensionnement empile un tween de plus sur des éléments qui n'existent déjà plus.

      


      

        

          
aria & ignore · rester lisible et cliquable

          
        

        
Un lecteur d'écran ne doit pas épeler les lettres une à une, et ce lien doit rester un lien.

        
aria: "auto"      → pose l'aria-label sur la phrase entière
ignore: "a"       → laisse le lien intact, non découpé
self.revert()    → restitue le HTML d'origine

Construis une page HTML autonome qui illustre tout ce que sait faire le plugin SplitText de GSAP, en quatre parties.

Découper : la même phrase découpée par caractères, par mots et par lignes, avec un bouton qui affiche les boîtes produites par le plugin pour qu'on voie ce qu'il fabrique dans le DOM.

Masquer : la même animation jouée côte à côte avec et sans l'option mask, pour montrer que sans masque le texte traverse l'espace au-dessus de sa ligne, et qu'avec masque il surgit de derrière un bord net.

Cadencer : le même fondu sur les caractères avec quatre ordres de décalage — du début, du centre, de la fin, au hasard — puis un exemple avec propIndex, où le décalage est calculé en CSS à partir de la variable écrite par le plugin, sans JavaScript d'animation.

Tenir : autoSplit avec onSplit qui renvoie son animation, pour que le texte se redécoupe au redimensionnement et que l'ancienne animation soit tuée proprement ; aria pour que la phrase reste lisible d'un lecteur d'écran ; ignore pour qu'un lien reste un lien ; revert pour rendre le HTML d'origine.
